# PayFlow — دليل التركيب السريع

هذه النسخة تستبدل تسجيل الدخول غير الآمن في الملفات القديمة بمصادقة Supabase Auth، وتضيف سجل عمليات موحدًا، طلبات الإيداع والسحب، التحويل الداخلي، التوثيق، الإشعارات، وواجهة إدارة كاملة.

## 1) تطبيق قاعدة البيانات

1. افتح مشروع Supabase.
2. انتقل إلى **SQL Editor**.
3. افتح الملف `supabase/setup.sql` من هذه الحزمة، وانسخ محتواه كاملًا ثم اضغط **Run** مرة واحدة.
4. إذا كانت لديك بيانات مهمة، خذ نسخة احتياطية قبل تشغيل أي ترحيل لقاعدة البيانات.

الملف يحافظ على الجداول الحالية ويضيف الحقول والجداول والسياسات المطلوبة. كما ينشئ مساحتين خاصتين للملفات: `deposit-proofs` و`kyc-documents`.

## 2) إنشاء حساب المدير

1. افتح `register.html` وسجل الحساب الذي تريد استخدامه كمدير.
2. بعد إنشاء الحساب، نفّذ السطر التالي في SQL Editor بعد استبدال البريد:

```sql
update public.users
set role = 'ADMIN'
where lower(email) = lower('admin@example.com');
```

3. سجل الخروج ثم ادخل مرة أخرى. ستظهر لك صفحة **إدارة المنصة**.

## 3) إعداد المصادقة قبل النشر

من Supabase انتقل إلى **Authentication → URL Configuration** ثم:

- ضع رابط موقعك الفعلي في **Site URL**.
- أضف رابط صفحة `login.html` ضمن **Redirect URLs**، مثل:
  `https://your-domain.com/login.html`

يمكنك تفعيل أو تعطيل تأكيد البريد من **Authentication → Providers → Email** بحسب سياسة التشغيل لديك. يوصى بإبقائه مفعّلًا للإطلاق الحقيقي.

## 4) رفع الموقع

ارفع كل ملفات ومجلدات حزمة `PayFlow` مع الحفاظ على الهيكل نفسه. يجب أن تبقى مجلدات `assets` و`supabase` في أماكنها. الملفات مناسبة للاستضافة الثابتة مثل GitHub Pages أو Cloudflare Pages أو Netlify.

## 5) أول إعداد داخل لوحة المدير

- حدّث سعر شراء وبيع USDT والعمولات.
- عدّل طرق الدفع الافتراضية وضع أرقام الحسابات الصحيحة.
- اختبر دورة كاملة بحساب مستخدم تجريبي: إيداع، قبول من المدير، تحويل داخلي، توثيق، ثم سحب.

## ملاحظات أمنية مهمة

- المفتاح الموجود في `assets/config.js` مفتاح **Publishable/Anon** ومسموح وجوده في الواجهة. لا تضع مفتاح `service_role` في أي ملف HTML أو JavaScript.
- كلمات المرور القديمة المخزنة في `password_hash` لا تُستخدم في هذه النسخة. الحسابات القديمة يجب ربطها بـ Supabase Auth عبر التسجيل/الاستعادة بالبريد. بعد التأكد، يمكنك تنفيذ سطر التنظيف الاختياري الموجود في نهاية `setup.sql` لمسح كلمات المرور القديمة.
- «حذف» العميل في لوحة الإدارة هو حذف آمن/أرشفة: يُجمّد الحساب مع الاحتفاظ بالسجل المالي لأغراض التدقيق، بدل حذف تاريخ العمليات نهائيًا.
- قبول الإيداع ورفض السحب وتعديل الرصيد كلها عمليات ذرّية داخل قاعدة البيانات، وليست تعديلات مباشرة من المتصفح.
